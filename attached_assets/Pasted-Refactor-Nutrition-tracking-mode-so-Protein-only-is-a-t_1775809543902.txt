Refactor Nutrition tracking mode so "Protein only" is a true simplified tracking mode, not just a visual emphasis mode.

GOAL

When the user selects "Protein only", the app should behave as a protein-only nutrition tracker.

That means:
- only protein matters for daily logging, scoring, and dashboard nutrition score
- calories, carbs, and fats should no longer be shown as active nutrition targets on this screen
- the UI should simplify accordingly
- switching into Protein only should require a confirmation step because it fundamentally changes how nutrition tracking works for the user

This is not "protein focus".
This is "track protein only".

--------------------------------------------------
1. TRACKING MODES
--------------------------------------------------

Support two mutually exclusive nutrition modes:

- Calories
- Protein only

Store as:
nutritionTrackingMode: 'calories' | 'protein_only'

Calories mode:
- existing nutrition model
- calories and macros can be shown
- dashboard nutrition score uses calorie adherence logic

Protein only mode:
- protein is the only nutrition target that matters
- calories, carbs, and fats should not be shown as active targets on the nutrition screen
- dashboard nutrition score uses protein-only adherence logic

--------------------------------------------------
2. CONFIRMATION WHEN SWITCHING TO PROTEIN ONLY
--------------------------------------------------

When the user taps "Protein only", do NOT switch immediately.

Show a confirmation modal.

Title:
- Switch to Protein only?

Body copy:
- This will simplify nutrition tracking to protein only.
- Calories, carbs, and fats will no longer be tracked as active targets on this screen.
- Your nutrition score will be based on protein logging only.

Buttons:
- Cancel
- Switch to Protein only

Behaviour:
- Cancel = stay in Calories mode
- Confirm = switch to Protein only

This is a settings confirmation, not a destructive delete flow.
Do not imply historical data is deleted unless that is actually true.

If historical calorie/macro data is still retained in the database, keep it retained.
Just stop using it for active scoring and active display while Protein only is enabled.

--------------------------------------------------

--------------------------------------------------

In Calories mode, keep the existing nutrition screen structure with any improvements already made.

Show:
- date selector

- remaining / target block with calories and macros
- add food / meal input

Calories mode can continue to show:
- calories
- protein
- carbs
- fats

Use the existing calorie-based scoring model.

--------------------------------------------------
4. NUTRITION SCREEN BEHAVIOUR IN PROTEIN ONLY MODE
--------------------------------------------------

In Protein only mode, simplify the screen clearly.

A. Top mode toggle
- show "Calories" and "Protein only"
- Protein only selected state should be visually obvious

B. Today status
Replace generic copy like "Nothing logged yet" with protein-specific status.

Examples:
- "Nothing logged yet"
- "42g protein logged"
- "18g to go"
- "Protein target hit"

C. Weekly strip
Weekly indicators should be based only on protein logging / protein target adherence.

Suggested logic:
- green = protein target hit
- amber = protein logged and within 20g of target
- grey = not logged or far off

D. Main nutrition summary card
Do NOT show calories, carbs, or fats as active targets.

Instead, replace the multi-metric remaining card with a protein-only card.

Show only:
- Remaining
- {remainingProtein} g
- Protein

Optional supporting text:
- "{loggedProtein}g logged today"
or
- "Nothing logged yet"

Do not show:
- calories remaining
- carbs remaining
- fats remaining

E. Add food / meal input
This can stay, but the parsed result should only matter for protein in this mode.

If the user logs a meal while in Protein only mode:
- still parse full nutrition if available internally
- but only surface protein to the user on this screen
- only protein should contribute to score

--------------------------------------------------
5. PROTEIN-ONLY SCORING LOGIC
--------------------------------------------------

When nutritionTrackingMode = 'protein_only', compute nutrition score from protein only.

For each day in the last 7 days:

logging_score:
- 1 if protein intake was logged that day
- 0 if not

accuracy_score:
- if protein >= target → 1.0
- if protein is within 20g below target → 0.8
- if protein is more than 20g below target → 0.4

Rules:
- do not penalise going over protein target
- if no protein target exists, fall back to logging_score only
- if not logged, accuracy_score = 0

daily_score = logging_score * accuracy_score
weekly_nutrition_score = average of daily_score over the last 7 days
nutritionPercent = Math.round(weekly_nutrition_score * 100)

Also calculate:
- loggedDays = number of days with protein logged
- hitDays = number of days protein target was met

--------------------------------------------------

If mode = calories:

- subtext: "{loggedDays} / 7 days logged"
- optional secondary line: "{closeDays} days close to target"

If mode = protein_only:
- primary stat: "{nutritionPercent}% on track"
- subtext: "{loggedDays} / 7 days logged"
- optional secondary line: "{hitDays} days hit protein target"

Keep the card label as:
- Nutrition

Do not create a separate Protein dashboard card.
