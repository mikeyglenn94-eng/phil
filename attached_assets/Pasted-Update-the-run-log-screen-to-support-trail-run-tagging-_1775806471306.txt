Update the run log screen to support trail run tagging and road-equivalent pace, while keeping the flow extremely simple for manual entry.

Goal:
Users can manually log a run, mark it as road or trail, and if trail is selected choose a trail difficulty. The app should then calculate and display an approximate road-equivalent pace. This is an MVP heuristic, not a full grade-adjusted pace model. It is inspired by the same basic idea used in grade-adjusted pace systems, where harder terrain should not be treated the same as flat road running. Strava describes GAP as an estimate of equivalent flat pace based on gradient.

Calculation rules:

- moderate = 0.92
- hilly = 0.86
- technical = 0.80

Formula:
equivalentRoadPaceSeconds = actualPaceSeconds * factor

Implementation details:
Create a utility for pace conversion and adjustment.

Example TypeScript:

const TRAIL_FACTORS = {
  moderate: 0.92,
  hilly: 0.86,
  technical: 0.80,
};

function toSeconds(pace: string): number | null {
  const match = /^(\d+):([0-5]\d)$/.exec(pace.trim());
  if (!match) return null;
  const min = Number(match[1]);
  const sec = Number(match[2]);
  return min * 60 + sec;
}

function toPaceString(totalSeconds: number): string {
  const rounded = Math.round(totalSeconds);
  const min = Math.floor(rounded / 60);
  const sec = rounded % 60;
  return `${min}:${sec.toString().padStart(2, '0')}`;
}

function getEquivalentRoadPace(
  pace: string,
  surface: 'road' | 'trail',
  difficulty?: 'moderate' | 'hilly' | 'technical' | null
): string | null {
  const paceSec = toSeconds(pace);
  if (paceSec == null) return null;
  if (surface === 'road') return toPaceString(paceSec);
  if (!difficulty) return null;

  const factor = TRAIL_FACTORS[difficulty];
  return toPaceString(paceSec * factor);
}
